Section 04

Product & Technology

A platform engineered from the ground up for West African commerce — mobile-first, mobile money native, built for 3G.

Product Overview

Emakola enables merchants — primarily Instagram sellers, WhatsApp traders, and market vendors — to create professional online stores with integrated payments, delivery logistics, and customer communication. Unlike global platforms retrofitted for Africa, Emakola is built from West Africa, for West Africa.

Two User Journeys, One Platform

Merchant journey: Sign up → Create store → Add products → Configure payments → Accept orders → Manage deliveries → Grow business.

Customer journey: Discover store → Browse products → Add to cart → Checkout with mobile money → Receive WhatsApp updates → Get delivery.

Merchant Admin Dashboard
  • Real-time order management with LiveView
  • Product catalog with variants, images, and inventory
  • Payment reconciliation across providers
  • Low-stock alerts and inventory tracking
  • Customer database with order history
  • Storefront theme customization
  • Analytics and sales reporting
Customer Storefront
  • Fast, mobile-optimized shopping experience
  • Product browsing with categories and search
  • Cart with mobile money checkout (MoMo, Telecel Cash)
  • Order tracking via WhatsApp and SMS
  • Cash on delivery with driver confirmation
  • Custom domain support (myshop.com)
  • SEO-friendly server-rendered pages

Technology Stack

Every technology choice was made with a single question: does this work better for a merchant on a 3G phone in Kumasi? The stack prioritizes low bandwidth, high concurrency, and operational resilience.

Layer Technology Why This Choice
Language Elixir 1.18+ / OTP 27+ Concurrency for 100K+ simultaneous connections, fault tolerance via supervision trees, hot code reloading for zero-downtime deploys
Web Framework Phoenix 1.8+ / LiveView Server-rendered pages with real-time interactivity — tiny JS payloads (~30KB), no client-side framework bloat
Domain Framework Ash 3.x Declarative resources with built-in multi-tenancy, authorization policies, and auto-generated APIs (GraphQL + JSON:API)
Database PostgreSQL 15+ JSONB for flexible product attributes, strong consistency, mature ecosystem, proven at scale
Background Jobs Oban Database-backed job queue with uniqueness constraints, cron scheduling, and guaranteed delivery for payment webhooks
Styling TailwindCSS Utility-first CSS with tree-shaking — small CSS bundles optimized for mobile-first design
Hosting Fly.io (Johannesburg) Edge deployment with ~80ms latency to West Africa, auto-scaling, built-in TLS, and Elixir clustering support
Payments Paystack + Hubtel Native Ghana and Nigeria coverage with mobile money APIs, card processing, and bank transfers

Why Elixir for Africa

Most African users are on 3G mobile devices with data budgets of 1-2 GB per month. Traditional React/Next.js single-page applications send 300KB+ of JavaScript before the page becomes interactive. Phoenix LiveView renders on the server and sends only DOM diffs over a persistent WebSocket connection — the initial page load is approximately 30KB of JavaScript. This is not a nice-to-have optimization. It is the difference between a 2-second page load and a 15-second page load on a typical Ghanaian mobile connection running at 300kbps. For merchants whose customers are deciding between your store and a WhatsApp message, those 13 seconds are the entire business case. Architecture Overview

Emakola uses attribute-based multi-tenancy powered by Ash Framework. Every tenant-scoped resource includes a store_id attribute, and every query is automatically filtered to the current tenant. There is zero risk of data leaking across stores.

Payment Gateway Abstraction

Payment providers are abstracted behind a Gateway behaviour, allowing new providers to be added without modifying checkout logic. The current implementation supports Paystack and Hubtel, with Flutterwave planned for the Nigeria launch.

Gateway Behaviour Interface
  defmodule Emakola.Payments.Gateway do
    @callback initiate_payment(map())           :: {:ok, map()} | {:error, term()}
    @callback verify_payment(String.t())        :: {:ok, map()} | {:error, term()}
    @callback process_refund(String.t(), integer()) :: {:ok, map()} | {:error, term()}
  end

Technical Moat

Why These Technology Choices Create Defensibility

The advantages described below are not features that competitors can replicate by installing a plugin or hiring a contractor. They are structural properties of the architecture that compound over time.

LiveView Performance Advantage

The performance gap between Emakola and React-based competitors is not incremental — it is structural. LiveView renders HTML on the server and sends only DOM diffs over WebSocket. A competitor would need to rewrite their entire frontend to match this performance on 3G networks. That is a multi-year, multi-million-dollar effort.

Enterprise-Grade Data Isolation

Ash Framework's attribute-based multi-tenancy provides data isolation at the query level from day one. Every database query is automatically scoped to the current store. This is not a middleware filter that can be accidentally bypassed — it is enforced by the framework itself across all 17 resources.

Fault-Tolerant Payment Processing

Elixir's OTP supervision trees ensure that payment webhook workers automatically restart on failure. Combined with Oban's database-backed job queue and uniqueness constraints, payment events are never lost — even during deployments or server failures. This is critical for mobile money transactions where callback reliability determines revenue.

Concurrency Without Complexity

The BEAM virtual machine handles 100+ concurrent checkouts without breaking a sweat. Each user connection runs in its own lightweight process (2KB of memory). While competitors provision larger servers or add caching layers to handle Black Friday traffic, Emakola scales linearly with the same codebase and infrastructure.
